Least privilege for AI agents, checked by a solver

Progent (Shi et al., UC Berkeley, arXiv 2504.11703) puts a policy between an agent and its tools. Every tool call is checked against symbolic allow/forbid rules over the tool's name and arguments, and anything unmatched is denied.

An LLM writes the first policy from the user's task, which is trusted, then proposes updates as tool results arrive, which are not. Z3 classifies each update: a narrowing is applied automatically, an expansion needs approval. The paper calls the result monotonic confinement: the agent's action space can only grow when someone says yes.

Everything below runs against a live backend. Decisions labelled reference come from the authors' code at commit 5be7b63. Decisions labelled paper semantics come from an independent checker written to the paper's definitions and to how the enforcer actually evaluates JSON Schema.

The shipped expansion check can fail open

The reference translator from regex to Z3 raises on ^, $ and \b, and the caller treats any exception as "no counterexample". A current policy with an anchored pattern therefore accepts any proposed update as a narrowing.

Separately, Z3 models a pattern as a full match while jsonschema enforces it with re.search. A pattern that looks identical to an exact value admits any string containing it. The containment checker and the attack lab both reproduce this.

Walkthrough: the paper's running example

The user asks the agent to carry out the TODOs in an email from Alice. Only after reading that email does the agent learn it must summarise recent mail and post to Slack. One of those emails tells it to forward the inbox to eve@evil.com. Step through to see the policy gating each call and how each update was classified.

Containment checker

    

      Is every call the new policy allows also allowed by the old one? If so the update is a narrowing and Progent
      applies it without asking. The paper-semantics checker searches for a call the new policy allows and the old
      one denies, then replays that call through the real enforcer as evidence.
    

    

    

    

      

        

        
        

      

      

        

        
        

      

    

    

    

  


  
  

    
Attack lab

    

      A real agent works in a sandboxed mock workspace while Progent sits between it and the tools. You choose the
      injection, how expansions are approved, and which implementation does the checking. The policy model uses
      the reference prompts verbatim.
    

    

      The attack lab needs an Anthropic API key on the server. Set ANTHROPIC_API_KEY in
      .env and restart.
